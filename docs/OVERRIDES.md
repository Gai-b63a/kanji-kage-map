# 根拠付き手動対応の保存と適用

`docs/overrides.jsonl` は候補の選択を明示する追記型記録です。対象ID・snapshot・候補版・典拠URLと所在・資料版・比較基準を持つレビュー原文とその正規化SHA-256、選択者の名前と人間／AI区分、日時、理由を保存します。初回の実記録はAIによるデータ整備判断で、人間の承認を意味しません。

今回の選択は「一」の `u4e00@46` をUnicode 18.0.0、日本典拠J0-306C、`structural_glyph_v1` に限って採用するものです。既に記録済みの構造一致レビューを根拠とし、新たな目視比較や他地域の一致を主張しません。

```text
python tools/lookup_override.py DATASET.sqlite3 docs/overrides.jsonl one-j0-306c-u4e00-46-20261104 --output selected.json
```

実取得したpreview.2 DBで実行し、選択対象のKAGE bundleを取得しました。結果の `scoped_selection` に選択条件と典拠を格納します。元のmappingと全候補、`selected_glyph: null` は保持され、無条件の確定対応へ変換されません。

選択に使用できるのは、DBに保持された有効な `whole_glyph` / `equivalent` レビューだけです。保存されたレビュー原文・ハッシュ、対象ID・snapshot・候補版を照合します。レビューが訂正・撤回された後に古い選択を再適用すると失敗し、新しい根拠による選択が必要です。

同じ対象・snapshot・典拠・基準の置換は `supersedes` で直前の選択IDを指定します。`action: revoke` で撤回でき、履歴は残します。撤回結果は選択字形を返しません。過去の分岐点からの訂正、重複ID、判断より前の選択日時を拒否します。

これは既存候補に対する範囲限定の手動選択経路です。候補にない字形を根拠なしに追加する処理ではありません。候補追加には、その字形の取得根拠と依存閉包を別途監査する必要があります。独立判断者間の承認権限・競合解決は未実装。今回のコードと選択記録はpreview.2公開後の追加で、同版ZIPには含まれません。

テストでは適用時の原レコード不変、撤回、旧選択の拒否、履歴分岐、候補版不一致、レビューの変更・非有効化を検査し、全77テストが通過しました。
