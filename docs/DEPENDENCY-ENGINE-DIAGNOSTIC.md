# 依存問題7候補のエンジン挙動

2026-11-04。実取得したpreview.2 DBから、既存の[依存問題追跡](DEPENDENCY-ISSUE-TRACES.md)の7候補を原KAGEのまま取得し、固定した `@kurgm/kage-engine@0.7.0` の明朝体・`kUseCurve=false` で診断した。[結果JSON](dependency-engine-diagnostic.json)に各原KAGEハッシュ、参照欠落の通知、展開ストローク数、出力ポリゴン数、SVGハッシュ、確認したエンジンソースのハッシュを保存した。

通常の `render_bundles.mjs` は依存問題のあるbundleを拒否する。今回の診断はその制御を変更せず、問題入力に対するエンジン単体の挙動を独立して観察したもの。

| 候補 | 原データの出力 | ポリゴン数 | 問題行をメモリ上だけで省略した比較 |
| --- | --- | ---: | --- |
| twedu-c15255-001@6 | 非空・出力座標は有限 | 32 | SVG一致 |
| hkcs_m28eb6@1 | 非空・出力座標は有限 | 69 | SVG不一致（ポリゴン数は69のまま） |
| hkcs_m29006@1 | 非空・出力座標は有限 | 44 | SVG一致 |
| hkcs_m31296@1 | 非空・出力座標は有限 | 86 | SVG一致 |
| lp_lps-00001460@1 | 空出力 | 0 | 欠落グリフの補完はしていない |
| hkcs_m7a81-p01-s00@1 | 非空・出力座標は有限 | 28 | SVG一致 |
| hkcs_m9d9f@1 | 非空・出力座標は有限 | 52 | SVG一致 |

省略比較は原因を切り分けるための反実仮想で、修正KAGEとして保存・配布・適用していない。省略する文字列と行番号は固定原本に照合し、依存先の別名にも同じ変更を適用した。原データを再取得して独立に再実行したところ、診断JSONはバイト一致した。

## 所見

- 欠落参照 `lp_lpy-00001460` はエンジンの欠落通知でも観測され、例外を投げず空出力になる。例外の有無だけでは検出できない。
- 空の命令タグを含む5候補は、当該行を除いた出力と同一だった。このエンジン・設定・入力に限る観測であり、意図的な無効行だったという作者意図の確認ではない。
- `hkcs_m28eb6@1` の非数値行 `s` は、省略前後でSVGが異なる。エンジンは数値変換後のストローク群をまとめて調整するため、不正行を削除しても他の輪郭に影響しないとは仮定できない。具体的な調整処理への原因帰属と、正しい字形の判定は未完了。

エンジンの `kage.js` は命令列を数値変換して展開し、`buhin.js` は未登録部品に対して既定で空文字列を返す。JSON内の `strokes_with_nonfinite_fields` は未使用の座標欄も数えるため、その件数を独立した不正ストローク数と解釈してはいけない。

7候補の `dependency_status: issues` は維持する。描画結果が有限・非空でも原KAGEの正当性や典拠字形との一致は証明されない。字形一致レビューは追加していない。

## 再現

```text
python tools/prepare_dependency_diagnostics.py DATASET.sqlite3 --output diagnostic-bundles.json
node tools/diagnose_dependency_rendering.mjs diagnostic-bundles.json diagnostic-results.json
```

描画エンジンは既存package-lockで固定する。診断コードは0.7.0以外を拒否する。今回の後続調査は公開済みpreview.2 ZIPには含まれない。
