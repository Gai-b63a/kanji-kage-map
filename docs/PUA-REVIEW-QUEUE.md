## 独立した未解決事項

主分類とは別に、採用表1.473と確認済みフォント1.472の版差をPUA全6,030件に記録しました。そのうち6件は当該フォントに見本がありません。番号付き部品121件には参照先PUA版が未指定という問題があります。これらは重複する件数なので主分類に足しません。

複数候補を持つ155件には候補を絞るための調査を、IDS記述が異なる番号付き部品11件には記述差を調べる作業を追加しました。原資料の版が確定するまでは、似た字形や同じPUA値を根拠に対応を継承しません。

各行の `blockers` はその字形の確認に不足している根拠です。プロジェクト全体の作業停止状態ではなく、他の出典調査などは並行して進められます。`next_actions` の意味は集計ファイルの `task_definitions` にあります。

## 版と再現

この一覧には[U+EADDの抽出修正](PUA-DISCOVERY-CORRECTION.md)が含まれます。初回配布版 `v0.1.0-preview.1` のDBは変更していません。候補名と版は同じGlyphWiki snapshotを使用しています。

```powershell
python -m kanji_kage_map pua-candidates --output data/generated/pua-source-id-fix
python tools/build_pua_review_queue.py
```

入力には固定原本、全件台帳、出典行、番号付き部品調査、フォント調査の結果を使います。台帳・候補・資料行と番号付き部品の集合一致、重複なし、原本ハッシュ、候補生成時の入力ハッシュ、フォント版不一致を検査してから一覧を出力します。入力ファイルのパスとSHA-256は集計に記録されています。原フォント・原表の本文を圧縮一覧に同梱しているわけではありません。

JSONLはUTF-8です。Python標準ライブラリで個別レコードを取得できます。

```python
import gzip, json
with gzip.open('docs/pua-review-queue.jsonl.gz', 'rt', encoding='utf-8') as stream:
    record = next(json.loads(line) for line in stream
                  if json.loads(line)['entity_id'] == 'babelstone:han-pua:1.473:U+EADD')
print(json.dumps(record, ensure_ascii=False, indent=2))
```

再実行した圧縮一覧のバイト一致、全6,151行のID一意性、各行に調査事項があることを確認しました。この一覧をレビュー結果に置き換える際は、対象版・比較した字形・具体的な差・判断者・日時を備えた別の判断記録が必要です。
