# 静的検査の所見が候補へ及ぼす影響

2026-11-04。全収録KAGEを対象とした[直接の静的検査](SYNTAX-AUDIT.md)を、依存辺を逆にたどって全候補へ伝播しました。候補自身に所見がなくても、参照部品に所見があれば対象とします。

| 母数・結果 | 件数 |
| --- | ---: |
| 走査した識別子 | 109,556 |
| 走査した候補リンク | 955,185 |
| 所見のある原グリフ | 418 |
| 所見へ到達する候補リンク | 554 |
| 自身に所見がある候補リンク | 414 |
| 依存先だけに所見がある候補リンク | 140 |
| 影響する識別子（重複排除） | 438 |

直接の所見がある候補にも、別の参照部品の所見が含まれる場合があります。上表の414と140は重複しない分類です。原グリフ418件には候補そのものではない依存部品も含むため、候補数と同じにはなりません。

| 所見 | 到達する候補リンク |
| --- | ---: |
| 非負整数という前提から外れる頭・尾指定 | 450 |
| エンジンの描画分岐にない命令 | 58 |
| 空欄数値の0変換 | 35 |
| 不正な命令タグ | 6 |
| 数値ではない欄 | 4 |
| 必要な数値欄の不足 | 1 |

理由別件数は重複します。これは**所見への到達性**であり、554候補すべての描画失敗や字形不一致を意味しません。欠落参照は元KAGEを検査できないため、この静的検査ではなく[依存監査](DEPENDENCY-ISSUE-TRACES.md)で扱います。

[全554候補の一覧](syntax-candidate-impact.jsonl.gz)には識別子、候補名と版、所見の発生元参照、理由、直接所見の有無を収録しました。[集計](syntax-impact-summary.json)には入力DB・直接所見・検査コード・出力のハッシュを記録しています。既存の対応状態は変更していません。

## 検証と再現

指定版を保った依存辺に対し、到達した `(候補, 所見発生元)` の組を重複排除します。同じ部品へ複数経路で到達しても水増しせず、循環があっても処理が終わります。別版の同名部品へ所見を移しません。

さらに全554候補を独立した通常のbundle取得で解決し、取得できた各原KAGEを再検査して、発生元の集合と理由の集合が伝播結果に完全一致することを確認しました。

```powershell
python tools/audit_syntax.py path/to/kanji-kage-map-v0.1.sqlite3
python tools/audit_syntax_impact.py path/to/kanji-kage-map-v0.1.sqlite3
```

直接監査と影響監査には同じDBファイルを使います。物理ハッシュが異なるDBでは、最初の直接監査から実行してください。原KAGEの修正や判断記録の追加は、この到達性集計とは別の作業です。
