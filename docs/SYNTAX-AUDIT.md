# KAGE静的検査

固定した `@kurgm/kage-engine@0.7.0` の実装を基準に、独立配布DB内の全1,201,970字形・2,759,959行を検査しました。418字形に要確認事項があります。原KAGEは変更・削除していません。

| 検出事項 | 欄／命令の件数 |
| --- | ---: |
| 非負整数というエンジン前提から外れる頭・尾指定 | 3,406 |
| 空欄をJavaScriptが0へ変換する数値欄 | 21 |
| エンジンの描画分岐にない命令（999） | 5 |
| 不正な命令タグ | 3 |
| 必要な数値欄の不足 | 2 |
| 数値ではない座標（116p） | 1 |

件数は候補数ではなく、全収録字形の直接の行・欄に対する検出数です。一字形の複数欄や複数行を含みます。負の調整値や無視される999命令は意図的な使用の可能性もあるため、すべてを破損や描画失敗と断定しません。

参照検査の「課題あり7候補」とは検査範囲・母数が異なります。新しい静的検査では頭尾形状の全組合せ、部品変形後の幾何学、重複点、描画結果、字形一致まで検証していません。また、この全件集計は依存先の所見をすべての候補へ伝播した件数ではありません。

`lookup --glyph` の結果には `static_syntax_audit` を追加しました。要求字形と取得できた全依存KAGEを重複なく検査し、参照名・行・原文・該当欄を返します。既存の `dependency_status`、`render_status`、`review_status` は独立して保持します。`no_findings` はこの静的検査で所見がなかったという意味に限られます。

例：`U+730B --glyph hkcs_m730b-p01-s00` では固定版 `@1` の12行目・9欄目 `116p` を検出します。数値へ修正してしまうことはありません。

## 再生成

```powershell
python tools/audit_syntax.py dist/kanji-kage-map-v0.1.sqlite3
```

`data/generated/syntax-audit/syntax-issues.jsonl` に全所見、`syntax-summary.json` に入力DB・検査コード・出力のハッシュと検査範囲を記録します。集計の公開コピーは [syntax-summary.json](syntax-summary.json) です。原本DBとコードがあれば追加パッケージなしで再生成できます。

## 規則の根拠

[KAGEエンジンの固定版0.7.0](https://www.npmjs.com/package/@kurgm/kage-engine/v/0.7.0) の `lib/esm/kage.js`（読取欄・伸縮処理）、`stroke.js`（命令の下2桁への分離）、`font/mincho/index.js`（描画分岐）、README（入力に対する前提）を確認しました。ファイルハッシュは [syntax-engine-sources.json](syntax-engine-sources.json) に保存します。

空文字と未定義欄はJavaScriptで扱いが異なるため別理由で記録します。また `99:200:0` はエンジン内部で伸縮なしへ変わり、後続の伸縮欄を使わないため、それらの省略を不足としません。通常のコメントや読み取られない末尾欄も数値欄として誤判定しません。
