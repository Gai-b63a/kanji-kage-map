- 確認済み対応は0件。関連字欄・字形名は探索根拠であり、字形の同一性・地域字形の正しさを保証しません。候補リストには採用済みグリフを設定していません。

## 実行方法

```powershell
python -m kanji_kage_map fetch-glyphwiki --lock glyphwiki.lock.json
python -m kanji_kage_map index-glyphwiki
python -m kanji_kage_map candidates
python -m kanji_kage_map resolve u6d77 --output data/generated/example-u6d77.json
python -m kanji_kage_map review-inventory
```

取得は既存lockを上書きしません。初回取得済みの環境では先頭コマンドは不要です。索引も既存DBを上書きしないため、再構築は `--database` と `--reports` で別の出力先を指定してください。アーカイブのハッシュ照合を通らない入力から索引は作成しません。

`resolve` はGlyphWiki名を入力する低水準CLIです。Unicode／版付きPUAの利用者向け検索APIは今後整備します。明示 `@版` は厳守し、無版参照は採用snapshot内の最新版へ解決。返却するbundleには元KAGE、版、関連字、資料行、依存辺の元参照・解決版、循環・欠落等の課題を含めます。非恒等参照も元KAGEのまま残します。

海 `u6d77` と龍 `u9f8d` はそれぞれ4グリフ・3依存辺を解決し課題0件でした。この2件は依存解決の確認であり、全候補の検証や目視レビューではありません。全候補の閉包監査・命令検査・描画検証は未実施です。
